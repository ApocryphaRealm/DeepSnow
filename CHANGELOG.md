# DeepSnow - changelog

Written as changes happen, not reconstructed afterwards (rule 61). Each version carries its
**version-ledger status**, so this file cannot quietly claim more than the ledger does:

* **working** - observed running in game
* **untested** - built and packaged, not yet confirmed
* **failed** - built but crashed or malfunctioned; the number was reclaimed
* **scratch** - a hypothesis-test build that never held a real number

## 1.1.0 - 2026-10-25 - untested

### Added
- Snow Deformation support: when Community Shaders' Snow Deformation feature is installed and switched on, the depth under each actor comes from its public API (SnowDeformation_GetAPI, version 1, resolved after kPostPostLoad and once more at data load; header include\SnowDeformationAPI.h, GPL-3.0-or-later, vendored unchanged). Its reading is in game units and already includes its accumulation, so it becomes % of a full blanket as 100 x units / fSDFullDepthUnits (default 30, its deepest default class at rest; its 1.5x accumulation peak reads 150 %), times Deep Snow's own trail packing. Deep Snow's own snowfall boost is not added on top. Roads, ice, a roof overhead and unread ground stay exempt; standing on an object keeps the OBJECT row. Landscape that no Deep Snow list names (OTHER) takes Snow Deformation's depth too, so a snow texture from any mod counts as soon as Snow Deformation sees snow there.
- New INI keys [Depth] uSource (0 Auto = Snow Deformation when it is on, else Deep Snow's own model; 1 own model; 2 Snow Deformation, falling back to the own model while it is off) and fSDFullDepthUnits (5 to 100); compiled defaults match the INI.
- Settings page: a Depth source choice (Auto / Deep Snow's own model / Snow Deformation), a Snow Deformation status line (found and on / found and switched off / not installed), the full-blanket slider when it is found, a Snow Deformation text for the depth explanation, and a note under Snowfall that its own snowfall is used while it is the source; every new string in all eleven languages.
- deepsnow.state reports depthSource, depthSourceSetting, sdFound, sdActive, sdUnits (the raw reading under the player) and sdFullDepthUnits.
- tools\check-band-mapping.cpp: an offline check of the Snow Deformation unit-to-band mapping against include\DepthMath.h, the arithmetic the plugin itself compiles (21 cases).
- Roads by name (the owner, 2026-10-25: any road or texture with "road" in its name is exempt, so road mods need no patch): a name containing "road" in any letter case makes the ground a road - the landscape texture's editor ID (LTEX), its texture set's editor ID (TXST), or its diffuse or normal path; for a mesh under the feet its path, its base object's editor ID or a diffuse texture its mesh draws (vanilla's Landscape\Roads\*.nif, Whiterun's WRMainRoad meshes, Dwemer roads). Roads are never slowed and never cost stamina. The case that prompted it: RoadsToCobblestone points Northern Roads' dirt roads at COTN_LRoadStone01, whose diffuse groundstone01.dds was in no list. ICE still comes first; the roof, object and other rules are unchanged. The rule lives in the new include\SurfaceRules.h (no game types).
- Deep Snow keeps the editor IDs the game drops at load (new source\EditorIDs.cpp): it wraps SetFormEditorID on the landscape texture, texture set and static vtables before the data loads and calls the original, so the road rule works without powerofthree's Tweaks (and still beside it). Landscape and texture set names are kept whole; statics only when the name says "road". The milestone-1 probe now names a landscape texture's editor IDs from this copy too.
- deepsnow.state reports landEditorId, textureSetEditorId, roadBy (the name that made it a road, or "sRoad" / "navmesh") and editorIdsKept; the [tick] debug line adds ltex and roadBy.
- Settings page: a line under the road note saying a road is any ground or object whose texture or name contains "road" and that the Road list is only for roads named otherwise, in all eleven languages.
- tools\surface_rules_check.bat: an offline check of the road rule against include\SurfaceRules.h and the shipped INI's lists (20 cases: the Northern Roads stone road with and without editor IDs, LRoad01, snow, vanilla road meshes, a dirt path, ice first, letter case); given a load order's landscape textures as a TSV it classifies every one.
- Optional setting [Roads] bPathsAreRoads, off by default (the owner, 2026-10-25: a toggle that also makes the rule apply to paths or footpaths, with a note about road mods that call their roads paths): when on, a name containing "path" (so "footpath" too), in any letter case, counts as a road exactly as "road" does, in the same names - LTEX and TXST editor IDs, diffuse and normal paths, and for a mesh its path, base editor ID and the diffuse textures it draws. It wins over the trail and snow lists; ICE still comes first; a name saying "road" is still preferred as the one reported. The case: Northern Roads' Seasons winter INI swaps its dirt roads to vanilla LDirtSnowPath01, which says no "road" and is on the trail list, so without the RoadsToCobblestone patch those roads read as trail (slowed) in winter. Settings page: a switch under the road settings with the note "Some road mods name their roads 'path' (for example Northern Roads' winter roads use a snowy path texture). Turn this on if roads from your road mod still slow you.", in all eleven languages; the INI comment says the same. Statics whose editor ID says "path" are now kept too, and a mesh's path texture is remembered beside its road texture, so the switch takes effect at once without a restart. Compiled default matches the INI (0).
- tools\surface_rules_check.bat: 13 more cases for bPathsAreRoads (LDirtSnowPath01 trail and LDirtPath01 other with it off, road with it on; diffuse-only and stem-only; FOOTPATH; ice still first; snow unchanged; a footpath mesh) - 33 cases in all.

### Changed
- sRoad is now an optional extra list for a road texture whose names never say "road"; its default entries are kept (the name rule already finds them). The INI's [Roads] and [Surfaces] comments say so.

### Fixed
- Precise sliders now clamp a typed value: every slider is drawn with ImGuiSliderFlags_AlwaysClamp and the value is clamped again after the call (include\PreciseSlider.h, from Dragon's Eye Minimap 7c3ce18). Typing a number above a slider's range (Ctrl+click) could otherwise leave it unclamped and re-applied every frame.
- A highlighted slider now steps on Left / Right without being activated, the same way everywhere on the page (the owner, 2026-10-25: one consistent way). Keyboard Left / Right and the D-pad move it one unit of its shown digit (with key repeat when held) and the highlight stays on it. In the depth-band table, Right used to move the highlight to the next column, and the keys changed a band value only after the slider was activated with A, Space or Enter (combined run 2026-10-25, request 04f6 step 8). Cause: Dear ImGui changes a slider from the keys only while it is the active item, so a slider that only held the highlight handed Left / Right to navigation, and in the table the next column's slider was to the right. New include\SliderNudge.h (precise::HighlightNudge) steps the value and cancels ImGui's navigation move on every frame the key is down. Up / Down still move between rows, and activating a slider still works as before. Proven offline by tools\slider_nudge_check.bat (32 checks against the framework's own ImGui build, including a control table drawn the old way that shows the fault).

## 1.0.0 - 2026-10-24 - untested

### Added
- Settings page on the Apocrypha Menu Framework: status under your feet, the depth-band table with precise sliders, switches, trail and snowfall settings, buttons that mark the ground under you as snow, trail, road or ice and save it, Save / Reload / Restore defaults; every string in eleven languages.
- DevBench tool deepsnow.control (forceband, mark, set, save, reload, restore, cleartrails, stamp) beside the extended deepsnow.state (tick, effects, settings, trails, probe).
- Optional faster travel on roads (off by default), optional snowfall deepening (off by default), NPCs and creatures optionally slowed too (off by default).
- Packed trails from every actor: a pass through a 128-unit square packs it, packing fills back in over game hours (faster while it snows), and the squares are kept in the SKSE co-save (record TRLS v1; APLD v1 remembers who holds an ability, SNFL v1 the snowfall boost).
- The surface table (SNOW, TRAIL, ROAD, ICE, plus objects and other ground) read from texture lists in the INI; ICE (frozenmarshice01/02 and ice meshes) is left to Ice is Slick - no slowdown and no stamina cost there.
- The depth model: Deep Snow's own estimate of the snow where an actor stands (the surface's depth x snow cover under the feet x trail packing x snowfall, 0 under a roof), measured in % of a full blanket (DTD's SnowRaiseHeight, read from its INI, for the units shown).
- Deep snow slows you and costs a little stamina: five configurable depth bands (a depth threshold, a speed and a stamina cost per second each), applied as SpeedMult ability effects from the new DeepSnow.esp (light plugin) that are added while you stand in a band and removed when you leave - never an absolute SpeedMult write, so they stack with Inertia, Dynamic Sprint and Survival Mode.
- Spike (milestone 1): a read-only ground probe. Twice a second it logs, for the player, the landscape texture underfoot (the engine's TES::GetLandTexture pick and the LAND quadrant's base texture and blend layers at the nearest vertex), the navmesh triangle underfoot and its preferred-path flag, a havok ray straight up (roof or overhang) and one straight down, and position, worldspace, cell, interior, mounted and swimming. DevBench tool deepsnow.state (op=state, op=history). Nothing in the game is changed.

### Changed
- deepsnow.state reports the land texture's LTEX form id (landTexture) beside its diffuse stem, so a road that shares a diffuse with snowy ground (vanilla snow cobble draws SnowRocks01) can be told apart; DevBench stamp credits its passes straight to the player's square.
- Default road textures are now vanilla road01* and Northern Roads' grounddirt01, grounddirt01_winter and grounddirt01_trail* (its LRoadDirt01 road and road-edge textures, met on the Whiterun stables road in test 78b3). snowcobble01 is dropped: vanilla's LSnowCobble01 draws SnowRocks01.dds, so that stem never matched.
- Roads are always exempt: no snow band and no stamina drain on a road, whatever the cover, packing or snowfall say (the owner, 2026-10-24). A road is the navmesh preferred-path flag, a texture in sRoad, or ground marked with This is a road. The optional road speed bonus is unchanged. Dirt and other non-snow ground stays penalty-free (fOther 0). The page says so in all eleven languages.
- ICE now matches Ice is Slick's own ice list, taken from Ice is Slick 1.0.3.2 (include\IceIsSlickTable.h): checked first by the collision material under the actor (MaterialIce 873356572 and MaterialIceForm 2431524493, new INI list sIceMaterials), then its 35 frozen-water meshes (sIceMeshes, exact paths; mesh paths now matched with forward slashes and no meshes\ prefix), then its ice texture names (sIce). ICE means no band, no stamina drain and no slowdown, so the two mods never act on the same ground. The DevBench state now reports the support material.
- The milestone-1 ground probe stays in the build but is off by default ([Probe] bEnabled=0); test 78b3 read what it was for.
### Removed
- The fRoad depth key: roads no longer have a depth row, they are always exempt.
### Fixed
- Loading a save no longer adds a pass of packing to every trail square someone is standing on: an actor first seen after a load only notes where it stands (test ff5b: +1 pass on all three restored squares).
- Untouched deep snow now reads a full blanket (100 %, band 5) under your feet: a pass of packing now counts on the square you leave, not the one you stand in, so you never stand in your own footprint (test ff5b read 85 %, band 4).
